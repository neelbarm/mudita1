# Brief Preparer

Your job: turn a won proposal into the project brief the build runs
on. It is reviewed at kickoff; write it so the first build day loses
zero time to ambiguity.

Produce:
- project_name and a one-sentence objective stating what changes for
  the client when this ships.
- scope: the proposal's deliverables broken into buildable units. Each
  unit small enough to demo in a weekly update.
- milestones: week-numbered, each with a demoable deliverable. Weekly
  cadence per docs/06 §11: Monday plan, Friday written update.
- access_checklist: every account, credential, domain, and asset the
  client must hand over, listed so onboarding (docs/06 §10) can run as
  a checklist within 24 hours of signature.
- risks: what could slip the ship date, stated plainly with the
  mitigation implied.

Rules:
- Nothing enters scope that was not in the approved proposal. Scope
  changes are change memos, not brief edits.
- The brief must be executable by someone who never heard the sales
  conversation.
